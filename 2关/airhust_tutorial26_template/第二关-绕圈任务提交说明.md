# 第二关正式任务：连续圆周飞行

## 1. 任务概述

本任务基于 `template` 个人副本实现完整流程：

```text
起飞 -> 到达圆周起点 -> 连续绕行一圈 -> 悬停 -> 降落
```

代码位于第二关工作空间：

```text
2关/airhust_tutorial26_template
```

开发分支：

```text
2.Circular-flight
```

本实现使用连续前方目标控制，不把圆分成少量离散航点。控制程序每轮根据实际位置计算当前圆周角，在当前位置前方选取目标点，再把目标位置误差转换为速度指令。

## 2. 实际参数

配置文件为：

```text
src/template/config/template.yaml
```

实际参数如下：

| 参数 | 数值 | 单位 | 含义 |
| --- | ---: | --- | --- |
| `circle_center_x` | 2.0 | m | 圆心相对起飞点的 x 坐标 |
| `circle_center_y` | 0.0 | m | 圆心相对起飞点的 y 坐标 |
| `circle_radius` | 2.0 | m | 圆周半径 |
| `circle_lookahead_deg` | 20.0 | deg | 前方目标相对当前位置增加的角度 |
| `circle_speed_max` | 0.5 | m/s | 水平合速度上限 |
| `err_max` | 0.15 | m | 固定位置任务的到达容差 |
| 目标 yaw | 0.0 | rad | 整个任务固定机头朝向 |
| `ALTITUDE` | 0.8 | m | 起飞和绕圈高度 |

默认圆心为 `(2,0)`，半径 2 m，因此圆周起点为：

```text
(2 + 2, 0) = (4, 0)
```

理论圆周长度为：

```text
2 * pi * 2 = 4pi = 12.57 m
```

若始终以 0.5 m/s 飞行，绕圈至少约需 25.1 秒；接近前方目标时比例速度会减小，实际耗时更长。

## 3. 修改的文件与职责

本次没有新增 C++ 源文件，也没有修改 `CMakeLists.txt`。

### 3.1 `template.h`

新增圆周状态：

```cpp
bool mission_circle_cruise_flag = false;
float circle_last_angle = 0.0f;
float circle_progress = 0.0f;
```

它们分别保存：

- 圆周任务是否已初始化；
- 上一控制周期无人机相对圆心的角度；
- 从开始绕圈到现在实际累计转过的角度。

新增函数：

```cpp
bool mission_circle_cruise(float center_x, float center_y,
                           float radius, float lookahead_angle,
                           float speed_max, float target_yaw);
```

函数负责计算圆周角、前方目标、速度目标、限速、实际绕圈进度和完成状态。

### 3.2 `template.cpp`

- 保存并从 YAML 中读取圆周参数；
- `case 2` 使用位置控制飞到圆周起点；
- `case 3` 每个控制周期调用 `mission_circle_cruise()`；
- 完成一圈后把 `mission_num` 设置为 `4`，进入悬停；
- 原有主循环继续以约 20 Hz 发布 `setpoint_raw`。

### 3.3 `template.yaml`

保存圆心、半径、前视角和速度上限，使这些参数可以在仿真前修改，而不需要修改 C++ 控制公式。

## 4. 完整任务流程

| 阶段 | 任务 | 完成条件 | 下一阶段 |
| --- | --- | --- | --- |
| `case 1` | 起飞 | 到达目标高度和 yaw 容差 | `case 2` |
| `case 2` | 飞到圆周起点 | x、y、z 和 yaw 进入容差 | `case 3` |
| `case 3` | 连续圆周飞行 | 实际累计转角达到 `2pi` | `case 4` |
| `case 4` | 悬停 | 悬停时间达到 3 秒 | `case 5` |
| `case 5` | 降落 | 降落流程完成 | 程序退出 |

其中 `case 2` 使用位置控制，因为圆周起点是固定点；`case 3` 使用速度控制，因为圆周目标随实际位置连续变化。

## 5. 数据就绪条件

任务开始前需要满足：

- MAVROS 状态显示 `connected: true`；
- 飞控进入 `OFFBOARD`；
- 无人机已经解锁；
- `/mavros/local_position/odom` 持续更新；
- 起飞阶段确认高度接近 `ALTITUDE`；
- 到达圆周起点后，圆周函数才初始化实际角度和累计进度。

程序通过 `local_pos_cb()` 保存最新位置反馈和 yaw。圆周函数不负责接收消息，而是直接使用已更新的 `local_pos`。

## 6. 圆周控制算法

### 6.1 计算相对圆心的偏移

```cpp
float offset_x = current_x - center_x;
float offset_y = current_y - center_y;
```

这里计算的是无人机当前位置相对圆心的偏移，不是无人机相对目标点的控制误差。

### 6.2 计算当前圆周角

```cpp
float current_angle = std::atan2(offset_y, offset_x);
```

`atan2(y, x)` 返回无人机在圆周上的方向角，单位为弧度。

### 6.3 初始化圆周进度

第一次进入圆周函数时记录实际角度：

```cpp
if (mission_circle_cruise_flag == false)
{
    circle_last_angle = current_angle;
    circle_progress = 0.0f;
    mission_circle_cruise_flag = true;
}
```

实际到达角度不一定严格为 0，因此不能把上一轮角度固定写为 0。

### 6.4 选择前方目标

```cpp
float target_angle = current_angle + lookahead_angle;

float target_x =
    center_x + radius * std::cos(target_angle);

float target_y =
    center_y + radius * std::sin(target_angle);
```

目标始终位于设定半径的圆周上，并比无人机当前位置向前约 20 度。

### 6.5 计算目标速度

```cpp
float error_x = target_x - current_x;
float error_y = target_y - current_y;

float velocity_x = position_gain * error_x;
float velocity_y = position_gain * error_y;
```

比例系数取 `0.5`。目标位置误差越大，速度越大；接近前方目标时速度减小。

### 6.6 限制水平合速度

```cpp
float horizontal_speed =
    std::sqrt(velocity_x * velocity_x +
              velocity_y * velocity_y);

if (horizontal_speed > speed_max)
{
    float speed_scale = speed_max / horizontal_speed;
    velocity_x *= speed_scale;
    velocity_y *= speed_scale;
}
```

限制的是水平合速度，而不是分别限制两个轴。这样斜向运动时也不会超过上限，并保持原速度方向。

### 6.7 填写控制消息

```cpp
float target_z =
    ALTITUDE + init_position_z_take_off;

float altitude_error = target_z - current_z;
float velocity_z = altitude_gain * altitude_error;

if (velocity_z > vertical_speed_max)
{
    velocity_z = vertical_speed_max;
}
else if (velocity_z < -vertical_speed_max)
{
    velocity_z = -vertical_speed_max;
}

setpoint_raw.type_mask =
    1 + 2 + 4 + 64 + 128 + 256 + 2048;
setpoint_raw.coordinate_frame = 1;

setpoint_raw.velocity.x = velocity_x;
setpoint_raw.velocity.y = velocity_y;
setpoint_raw.velocity.z = velocity_z;
setpoint_raw.yaw = target_yaw;
```

该掩码表示：

- 忽略位置 x、y、z；
- 使用速度 x、y、z；
- 忽略加速度和力；
- 使用 yaw；
- 忽略 yaw rate。

`coordinate_frame = 1` 沿用本地固定坐标系。速度轴不随机头 yaw 旋转，`yaw` 只控制机头朝向。

竖直方向使用高度反馈。`altitude_gain` 取 `0.5`，`vertical_speed_max` 取 `0.2 m/s`。当前高度低于目标时产生向上修正速度，当前高度高于目标时产生向下修正速度。

## 7. 圆周进度与完成判断

每轮计算实际角度差：

```cpp
float raw_angle_delta =
    current_angle - circle_last_angle;

float angle_delta =
    std::atan2(std::sin(raw_angle_delta),
               std::cos(raw_angle_delta));

circle_progress += angle_delta;
circle_last_angle = current_angle;
```

第二行把角度差映射到 `-pi` 到 `pi` 范围，避免从约 180 度跨到约 -180 度时出现约 360 度的假跳变。

完成条件是实际累计转角达到一整圈：

```cpp
if (std::fabs(circle_progress) >=
    2.0f * static_cast<float>(M_PI))
{
    setpoint_raw.velocity.x = 0.0f;
    setpoint_raw.velocity.y = 0.0f;
    setpoint_raw.velocity.z = 0.0f;

    mission_circle_cruise_flag = false;
    circle_last_angle = 0.0f;
    circle_progress = 0.0f;

    return true;
}
```

完成后主循环仍会发布这一帧零速度目标，实际停止还需要飞控响应和短暂减速过程。返回 `true` 后，`case 3` 把任务切换到悬停。

不能把“到达第一个圆周点”作为完成条件，否则无人机刚到达圆周起点就会被误判为完成一圈。

## 10. 参数调整与现场验证

| 参数变化 | 预期变化 |
| --- | --- |
| 半径从 2 m 增大到 3 m | 圆周起点变为 `(5,0)`，圆周长度和运行时间增加 |
| 前视角从 20 度增大 | 前方目标更远，跟踪可能更快，但更易内切或振荡 |
| 速度上限从 0.5 m/s 提高 | 理论耗时缩短，但惯性引起的过冲可能增加 |
| 前视角过小 | 目标离当前位置太近，跟踪可能缓慢或不稳定 |

现场验证选择修改 `circle_radius`，将半径从 `2.0` 调整为 `3.0`。此时圆周起点由 `(4,0)` 变为 `(5,0)`，圆周长由约 `12.57 m` 增加到约 `18.85 m`。在速度上限和其他参数不变时，预期圆周轨迹变大且绕行耗时增加。

## 11. 调试问题与解决

### 问题一：角度定义不一致

最初容易把角度计算写成 `atan2(offset_x, offset_y)`，同时目标坐标使用 `x=cos`、`y=sin`。这两种定义不配套，会使目标角度和实际方向不一致。

解决方法是统一采用：

```text
current_angle = atan2(y, x)
target_x 使用 cos
target_y 使用 sin
```

### 问题二：编译错误

实现过程中出现过圆周函数缺少 `return false`，以及 `case 3` 重复的问题。前者会导致函数没有完整返回值，后者会产生重复 `case` 编译错误。

### 问题三：绕圈时高度漂移

完整运行后，圆周任务在水平方向完成一圈并进入悬停，但悬停日志记录的位置为：

```text
Hovering at (3.68, -1.10, 1.97)
```

设定高度 `ALTITUDE` 为 `0.8 m`，实际高度约达到 `1.97 m`，说明绕圈过程中存在明显的高度漂移。

首次完整圆周运行后，圆周控制中一直发送：

```cpp
setpoint_raw.velocity.z = 0.0f;
```

竖直目标速度为零只能抑制持续升降，没有根据实际高度主动修正。增加高度反馈：

```text
当前高度误差 = 目标高度 - 当前高度
竖直修正速度 = 高度增益 * 高度误差
```

最后把竖直修正速度限制在 `-0.2 m/s` 到 `0.2 m/s`，再写入 `setpoint_raw.velocity.z`。水平方向继续追踪圆周目标，竖直方向同时把无人机拉回设定高度。

修改后的圆周控制实时读取 `current_z`，使用 `ALTITUDE + init_position_z_take_off` 作为高度目标，并在日志中同时输出当前高度和竖直速度：

```text
circle progress: ... altitude: ... vz: ...
```

修改后的验收目标是让绕圈和悬停高度保持在约 `0.8 m`，避免此前持续漂移到接近 `2 m` 的现象。最终提交前应重新编译并运行一次，以日志中的实际高度作为高度反馈是否有效的依据。

## 12. 重启与复现

重新运行时：

1. 在任务终端按 `Ctrl+C` 停止 `template`；
2. 在仿真终端按 `Ctrl+C` 停止课程仿真；
3. 重新启动 `roslaunch simulation sim.launch`；
4. 重新执行 `rosparam load`；
5. 重新运行 `rosrun template template` 并输入 `1`。

圆周任务完成时会复位圆周状态。重新启动节点后，全局状态也会重新初始化。
