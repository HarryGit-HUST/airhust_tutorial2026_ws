## 二、短练习：从“去哪里”到“怎样移动”

之前的位置任务告诉飞控“希望到这个位置”。现在试着换一种要求：告诉飞控“沿某个坐标方向，以多大的速度移动”。

例如，position.x 写入 1.0，表达的是目标 x 坐标；velocity.x 写入 0.5，表达的是沿 x 正方向的目标速度为 0.5 m/s。速度为负值时，要求向该坐标轴的负方向移动。这里使用本地坐标轴，不能直接把正负方向理解成机头前后。

请先按下面的过程推演，说明怎样用速度指令接近一个目标点，再停下来。本题提交计算思路、关键代码片段与停止条件即可，可以在个人仿真副本中进一步验证。

### 1. 先让飞控读取速度字段

沿用原包的 coordinate_frame = 1，先固定 yaw = 0。下面这个掩码忽略位置、加速度和 yaw_rate，使用三轴速度与 yaw：

```cpp
setpoint_raw.type_mask = 1 + 2 + 4 + 64 + 128 + 256 + 2048;
setpoint_raw.coordinate_frame = 1;
setpoint_raw.yaw = 0.0;
```

这里没有加入 8、16、32，所以 vx、vy、vz 会被使用。512 是力模式标志，三个加速度 / 力字段都忽略时，本题不需要它。

改掩码只决定“读哪些字段”，还要自己给这些字段赋值：

```cpp
// 提示：需要根据本轮计算结果填写这些字段。
setpoint_raw.velocity.x = /* 本轮的 vx */;
setpoint_raw.velocity.y = /* 本轮的 vy */;
setpoint_raw.velocity.z = /* 本轮的 vz */;
```



### 2. 先只想一个方向：离目标越近，速度怎样变化

假设目标 x 为 2 m，当前 x 为 0 m。如果一直发送固定的正速度，经过目标后它仍会继续要求向正方向运动。程序需要利用新位置反馈，重新计算速度。

一个起步思路是：**用“目标位置减当前位置”得到误差，让目标速度与误差成比例。**

\[
e_x=x_{\mathrm{target}}-x_{\mathrm{actual}},\qquad v_x=k e_x
\]

k 是正的比例系数。比如取 k = 0.5 s⁻¹：

| 本轮当前 x | 到目标 x = 2 m 的误差 | 计算出的目标 vx |
| --- | --- | --- |
| 0 m | 2 m | 1 m/s |
| 1.8 m | 0.2 m | 0.1 m/s |
| 2.1 m | -0.1 m | -0.05 m/s |

从这三行体会：远时要求快一些，近时要求慢一些，超过目标后要求往反方向调整。



### 3. 再扩展到三个方向，并限制速度

y、z 方向也可以用同样的误差思路。不过我们直接把 vz 设为 0，表达的是目标竖直速度为 0。

位置误差较大时，直接相乘可能得到过大的速度，还需要设置速度上限。例如，把水平合速度限制在自己选定的上限内。

请说明你的限速方法，并注意分别限制 vx、vy 与限制合速度的区别。

### 4. 接近目标后，让任务能够结束

可以沿用原位置函数的到达条件：各轴位置误差小于 err_max，yaw 误差满足原条件后，将三轴目标速度置为 0，再报告当前任务完成。这里固定目标 yaw 为 0，比较时也要使用这个目标。

写入零速度后，还要经过发布，飞控才能收到这一要求；实际运动也需要过程。

## 三、正式任务：设计自己的绕圈飞行

> 基于 template 的个人副本，实现“起飞 → 到达圆周起点 → 绕行一圈 → 悬停 → 降落”。自行设计圆周目标的生成方式、推进方式和完成判断，并将至少一个绕圈参数放入 YAML。

这次重点看自己的理解，现场需要解释代码，并修改一个参数验证。


### 1. 共同的几何起点

一个水平圆可以写成：

\[
x=c_x+r\cos\theta,\qquad y=c_y+r\sin\theta,\qquad z=h
\]

`(c_x, c_y)` 是圆心，`r` 是半径，`h` 是高度，`θ` 是从圆心看向目标点的角度，使用弧度。改变 `θ`，就能得到圆周上不同的目标。

如果通过 `mission_pos_cruise()` 发送这些值，要记得它会给 XYZ 加上记录的初始位置。因此，上式的圆心、目标和实际反馈必须先放到一致的坐标参考中理解。

下面三种设计都可以使用这组公式，区别是：**下一次的 θ 怎样确定，以及怎样判断实际完成了一圈。** 你也可以提出其他合理方案。

### 2. 思路 A：离散航点，先把圆分成若干点

将一圈分成 `N` 份，第 `k` 个目标角度可以表示为：

\[
\theta_k=\theta_0+s\frac{2\pi k}{N}
\]

`θ₀` 是起点角度，`s` 取 `1` 或 `-1` 表示相反的绕行方向。`N` 可以先选一个便于观察的数量，例如 12，再比较改变点数后的效果。

执行过程：先到圆周起点；生成当前航点；反复发送该目标并检查是否到达；到达后才推进到下一个航点；最终回到起点附近，结束一圈。

你需要保存当前航点编号，并处理一圈末尾的闭合。航点过少时轨迹会显得像多边形，点数增多、到达误差改变，也会影响运行过程。这些都可以通过实验观察。

### 3. 思路 B：让角度随时间变化

到达圆周起点后记录开始时刻 `t₀`，用时间生成目标：

\[
\theta(t)=\theta_0+s\omega(t-t_0),\qquad \omega=\frac{2\pi}{T}
\]

`T` 是目标绕行一圈的周期，`ω` 是目标角度变化的速度。每次主循环读取当前时间，算出新的角度，再生成并发送目标点。

这种方式需要思考目标变化与实际跟踪的关系：如果目标已经走完一圈，飞机却落在后面，该怎样收尾？你需要保留实际轨迹或进度证据，并设计相应的完成判断。

如果继续使用 `mission_pos_cruise()`，要考虑目标每轮都在移动，它的“是否到达当前点”返回值应该怎样使用；不应机械套用固定航点的推进方式。

### 4. 思路 C：根据实际位置选择圆周前方目标

将实际位置换算到与圆心相同的坐标参考中，计算当前围绕圆心的角度：

\[
\phi=\operatorname{atan2}(y_{\mathrm{actual}}-c_y,\ x_{\mathrm{actual}}-c_x)
\]

再把目标放在当前角度前方：

\[
\theta_{\mathrm{target}}=\phi+s\delta
\]

`δ` 是向前看的角度。把这个角度代入圆周公式，得到下一个目标。随后接收新位置，再重新计算前方目标，让目标的推进与实际运动联系起来。

同样要先到达圆周起点，再进入这一过程。你需要考虑前视角大小、实际半径偏差，以及怎样记录一整圈进度。角度跨越正负 π 时会跳变，直接比较单次角度通常不足以表示已绕行多少。

### 5. 选择方案并说明自己的判断

选择一种方案开始，先把完整流程做出来。可以组合方案，也可以提出其他目标生成方法，只要能解释它怎样与反馈和主循环配合，并展示实际效果。

在 YAML 中加入至少一个自己会读取的绕圈参数，例如半径、航点数量或周期；写明参数名称和单位。

完成基础任务后，可以自行选择多圈、方向切换、速度变化等拓展。
